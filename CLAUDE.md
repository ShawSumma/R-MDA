# r-mda

RWKV-7 blocks trained as a masked-diffusion text denoiser jointly with AR, initialised from and distilled out of SmolLM2-135M, in raw Vulkan compute (C host + GLSL).

## Rules

- Run `build/bench` before and after a performance change; its per-kernel GPU profile says where the time goes.
- Any buffer the host reads back is `mda_vkc_alloc_cached`; bulk host reads of device-local buffers go through a cached staging buffer and `mda_vkc_copy`.
- A change to what the parameters mean (their order, or a formula that reads them) bumps `MDA_CKPT_MAGIC` in src/ckpt.h; the header only catches config and layout-size changes.
- The tokenizer is SmolLM2's (`tools/fetch_smollm.py` writes `models/tokenizer.txt`); after changing the corpus, the token-id cache rebuilds on the next load. Checkpoints trained on another vocab are refused.
- If train stops with "overflowed", run `build/probe_acts` on `models/ckpt-overflow.bin` before changing anything.
- Python tools run from `.venv` (pyarrow is installed there).
- Compare training changes with `tools/logstat.py` on runs from the same seed: batches are a hash of the step, so the runs are paired.

## Style

- C17 (`-std=gnu17`), no C23 features: `bool` comes from `<stdbool.h>`, no typed enums, no `{}` initializers.
- Every name carries the namespace `mda_` plus its file's name: `mda_fwd_rec`, `mda_fwd_act_t`, `MDA_MODEL_MAX_PARAMS`; a program's own functions use its file name too (`mda_train_lr`).
- Headers hold, in this order: includes, defines, typedefs, enums, structs, prototypes. `.c` files hold only includes and functions. Order declarations by dependency and use, not alphabetically.
- An enum is a `typedef uint32_t x_t;` in the typedefs plus an anonymous `enum { ... }` of its constants after them; never a typedef merged with the enum.
- Struct members are laid out to avoid padding, with bools last.
- No comments (C, GLSL, makefile, Python). No `static`, `inline`, function bodies in headers, `exit()`, ternaries, `++`/`--`, out parameters, `qsort`, `rand`/`srand` (pseudo-randomness comes from `src/hash`), or plain `int` (except `main`).
- No side effects in a condition, including calls that write or print. No reassigned status flags. No guard clause that returns and falls through to more code: when one branch returns, the rest goes in `else`; split long functions into stages instead of nesting.
- Use `switch` to dispatch on a value. Each call and signature sits on one line, or one argument per line with the closing `);` on its own line.
- printf padding only in tables with a header row; no decorative output.
- The makefile uses `!=`, `${VAR}` and `${VAR:%.c=%.o}`, not GNU functions or `:=`; header dependencies come from the compiler (`-MMD -MP`).

## Code structure

- `makefile` -- `shader/*.comp` -> `build/*.spv` (glslc); the modules in `MODS` -> `build/obj/*.o` -> `build/libmda.a`; each program in `PROGS` (`src/<name>.c`) -> `build/<name>` linked against it; `build/**/*.d` hold the header dependencies. `make test` runs every `build/test_*`. Binaries load `build/*.spv`, `data/corpus.txt` and `models/` by relative path, so run them from the project root.
- Errors return to `main` as `false`/NULL/`ok` results: a Vulkan or config failure sets the sticky `mda_vkc_t.fail` (every vkc call is then a no-op).
- `tools/fetch_corpus.py` -- downloads FineWeb-Edu shards into `data/fineweb-edu/` and writes their text as `data/corpus.txt`; run it with `.venv/bin/python3` (pyarrow).
- `tools/fetch_smollm.py` -- downloads SmolLM2-135M's `tokenizer.json` and weights (`models/smollm2.safetensors`) and writes `models/tokenizer.txt`: the byte-level BPE vocab as raw bytes in id order, then the merges in rank order as "left right merged" ids.
- `tools/gen_unicode.py` -- writes `src/unicode.c` (the letter and number code point ranges the GPT-2 pre-tokenizer regex uses) from Python's unicodedata.
- `tools/check_tokenizer.py` -- compares `data/corpus.txt.ids` with Hugging Face `tokenizers` on the start of the corpus (needs that package, not in `.venv`).
- `tools/check_teacher.py` -- compares `build/check_teacher`'s logits with SmolLM2 in Hugging Face `transformers` (needs torch and transformers, not in `.venv`).
- `tools/logstat.py` -- mean loss and bits/byte over a window of steps of `build/train` logs (`--last`, `--end`).
- `tools/sweep.py` -- one `build/train` run per learning rate with the other arguments shared, logs written next to the checkpoints (`models/NAME-LR.log`), then a logstat comparison.
- `tools/compare.py` -- one `build/train` run per variant (name, mode, checkpoint to start from, teacher, teacher share) with lr, steps, accum, optimizer and batch shared, each then evaluated by `build/sample`; writes `models/GROUP-NAME.bin/.log/.eval` and a table of NELBO, AR NLL, fill accuracy and s/step to stdout and `models/GROUP.table`.
- `tools/vast_wait.py` -- polls a vast.ai instance (through the `vastai` CLI in `.venv`) until it runs, then prints its ssh addresses.
- `tools/strip_ckpt.py` -- copies a checkpoint's header and weights into a weights-only file.
- `src/vkc` -- Vulkan harness: device selection + feature checks, device-local (`mda_vkc_alloc`, never mapped, counted in `dev_bytes`) vs host-cached (`mda_vkc_alloc_cached`) buffers, views, copy/fill, `mda_vkc_read`/`mda_vkc_write` (a whole buffer to or from the host through a staging copy), kernel loading, dispatch. `mda_vkc_begin`/`mda_vkc_flush` record a transient batch into one submit, `mda_vkc_record`/`mda_vkc_end`/`mda_vkc_submit` a persistent command; outside a batch every `mda_vkc_run` is its own submit + wait. Also the per-kernel GPU timestamp profiler.
- `src/pc.h` -- push-constant layouts of every shader, `MDA_PC_NO_SLOT`, the vecops ops.
- `src/hash` -- pure hash of (stream, key, index) to integers, uniforms and normals.
- `src/sort` -- heapsort of (key, index) pairs, ties broken by index.
- `src/util` -- clock, path suffixing, argv defaults, ok/FAIL, min/max.
- `src/unicode` -- generated letter and number range tables and their binary-search lookups.
- `src/tokenizer` -- SmolLM2's byte-level BPE: tokenizer file read, merge table (open addressing on the id pair), encode (every Unicode number isolated, then the GPT-2 regex pre-tokenizer, then the lowest-rank merge, leftmost first, until none applies; bytes without a token are dropped, as in Hugging Face), tokenizer hash, corpus and tokenizer paths.
- `src/data` -- loads the tokenizer and tokenizes the corpus on every core into `data/corpus.txt.ids` (reused while tokenizer and corpus are unchanged; last 1% held out as the eval split); threads and windows are cut only where a printable ASCII byte meets a newline, a pre-token boundary, so the ids equal tokenizing the whole text. `mda_data_batch` fills a batch (ids, target, mask, loss weight) as a function of its key (the training step), so a run is reproducible and a resume never replays batches. Schedules: `BELL` (diffusion training: t from a truncated N(0.5, 0.1), unweighted loss), `ELBO` (evaluation: t uniform on (0, 1], 1/t weight, so the loss is the NELBO), `AR` (next-token targets, nothing masked).
- `src/safet` -- safetensors reader (bf16 tensors by name, minimal header parse), bf16 copies into fp32, HF linear [out, in] -> [in][out] with grouped heads repeated.
- `src/model` -- config (`mda_model_cfg`: SmolLM2-135M's shape, d 576, 30 layers, 9 heads, FFN 1536; checked by `mda_model_init`), parameter registry (`mda_model_param_t`: views of w, g, AdamW moments and fp16 mirror into per-role arenas, plus the transposed fp16 mirror; init normal, constant or RWKV-7's decay speed), the per-layer low-rank MLPs (`mda_model_lora_t`: w tanh, a, v, g sigmoid), kernel handles.
- `src/fwd` -- the GPU optimizer state block (`mda_fwd_opt_t`), scratch buffers (with the host batch view of the inputs), per-layer saved activations (`mda_fwd_act_t`), dispatch helpers, mirror refresh, and the one forward (`mda_fwd_rec`: embed, adaLN with a per-layer scale/shift vector `ada` (the network gets no mask rate, as in RADD; read times `mda_model_ada_scale` = sqrt(d/2) and updated with that AdamW lr multiplier), blocks, head tied to the token embedding) shared by training and inference; `mda_fwd_run` wraps it for eval/generation. The time mix is RWKV-7's: token shift, k, v, r from full matrices and w, a, the value-residual gate and the output gate g from low-rank MLPs (first stages, activations and second stages each batched), `heads_fwd` turning them into the per-head removal key kappa-hat = norm(k * xi), replacement key k~ = k * lerp(1, a, alpha), decay w = exp(-e^-0.5 sigmoid(.)), a = sigmoid(.), the value residual v = lerp(v0, v', sigmoid(.)) (v0 is layer 0's value), and the bonus scalar sum(r * rho * k~) per head, packed into one six-section buffer; the recurrence S'[i][e] = w[i] S[i][e] - a[i] kappa[i] (S^T kappa)[e] + k~[i] v[e] (decay on the key channel; `wkv7_fwd` runs one workgroup per sequence, head and direction, four adjacent lanes per value column holding 16 key rows each, so both per-step sums are clustered subgroup adds and the only barriers load 4 steps of inputs, prefetched; it saves the state every 4 steps in fp16 and (S^T kappa) per step for the backward); `wkv_out` per-head RMS norm + bonus * v, times g. The residual stream lives in the layers' `x_in` / `x_mid`: each sublayer's last matmul writes prev + its product straight into the next one (the last layer into `x`). Each layer keeps the fp16 copies (and scale slots) of the activations its matmuls read, so the backward reuses them; the FFN's `elem` computes silu(gate) * up with its absmax in one pass, and the backward recomputes silu from `gate_pre`. The loss pass (`softmax_ce` op 0) leaves the logits alone and keeps each row's logsumexp and its gradient's absmax; the backward writes the logit gradient from them straight to fp16 (op 2, op 1 in fp32 for ref32). Its first `soft_rows` rows (a teacher's rows) take the teacher's distribution, mixed with the one-hot target by `teach`, as the target: gradient p - target, while the logged loss stays the cross-entropy against the real next token. Generation also gets each row's confidence (the sampled token's probability). With `mda_model_t.causal` set at record time only the left-to-right wkv pass runs, making the same network an AR model. A config with `block` (`mda_model_cfg_block`, mode names `block` / `block<n>`) is block diffusion jointly with AR: the batch's first half holds the second half's windows unmasked, run causally with next-token targets (the AR loss); each noisy block's left-to-right wkv pass starts from the clean rows' state at the block start (`bstate`, its gradient flows back through `dbstate`), its right-to-left pass and token shift stay inside the block. `mda_model_t.dec` (mode `block<n>d<D>`, `mda_model_set_dec`, set before recording) splits block mode into encoder and decoder with shared weights (E2D2's shared-KV variant): the bottom L-D layers run only the clean rows, the noisy rows enter at layer L-D with their embeddings (copied into that layer's `x_in`) and take the value residual's v0 there, and each decoder layer's noisy wkv still starts from the same layer's clean state. Record-time row counts come from `mda_model_t.live` (`mda_fwd_set_live`, `mda_fwd_rows`); sections, embed, head and loss stay full-batch, and the noisy rows of the embedding gradient come from layer L-D's input gradient. Checkpoints only record the parameter shapes, so the same weights load as AR, diffusion, block diffusion or split block diffusion. With `cache` set (`mda_fwd_cache_t`: per-layer clean wkv state and token-shift carry, double buffered) the clean rows start from the cached state and write their end state to the other buffer, which `mda_fwd_cache_commit` makes current; a block-length model then continues a sequence one block at a time, exactly as the full-length model would. With `stage` set, `mda_fwd_run` also writes the temperature softmax of every row there in the same submit.
- `src/bwd` -- matmul backward helpers (scalar in ref32): weight grads read the saved fp16 activation and the output grad transposed in place (`MDA_FWD_AT`), input grads multiply by the transposed fp16 weight mirror and can accumulate. `mda_bwd_mm` takes the output grad's fp16 scale slot from the caller: `elem`, `heads_bwd`, `lora_act` and `wkv_out` fold the absmax of what they write into their own pass. The fp16 matmul (`mda_fwd_mm16_epi`) takes the operand layout (`MDA_FWD_AB`/`AT`/`BT`, loops specialized per layout outside the k loop) and an output stage `alpha * AB + beta * prev` (`prev` may be the output itself) stored as fp32, fp16 or both, optionally symmetric (`MDA_FWD_STORE_SYM`: only tiles on or above the diagonal run and mirror themselves; the 64x64 kernel only). It runs the 128x128 kernel (2x2 subgroups of 64x64 each, subgroups past m or n idle) when that gives at least `MDA_FWD_WIDE_GROUPS` workgroups, else the 64x64 one (2x2 subgroups of 32x32). Both stage A and B through shared memory in steps of 32 along k, double-buffered, with 128-bit loads, and load the cooperative matrices from shared memory: k must be a multiple of 32 and every operand offset 16-byte aligned. Loading cooperative matrices straight from global memory ran at about 20 TFLOPS on NVIDIA drivers before 615.
- `src/teacher` -- an AR Llama teacher (SmolLM2) for distillation: weights from safetensors into one fp32 arena + its fp16 mirror and the transposed fp16 embedding, and a forward recorded into the caller's command (embed, per layer RMSNorm, q/k/v matmuls, in-place RoPE, causal grouped-query attention with an online softmax over 64-key tiles in shared memory, o + residual, SwiGLU, logits over the student's vocab) on the first `rows` of the student's batch.
- `src/step` -- `mda_step_trainer_t`: three persistent commands, forward + backward writing the grads (first micro-batch) or adding to them (the rest), and the optimizer (grad norm, clip, dynamic loss scale with overflow skip, Muon's Newton-Schulz update on the hidden matrices (k, v, r, o and the FFN; the low-rank MLPs and vectors use AdamW), each iteration three matmuls whose output stages do the polynomial and the update (the Gram matrix and the polynomial are symmetric), with AdamW per parameter (its `lr_mul`) for the rest or AdamW alone, mirrors). With a teacher, each micro-batch first records the teacher's forward. The time-mix backward: `wkv_out` backward, the recurrence backward per direction into a six-section gradient buffer (in block mode the noisy rows' backward runs one workgroup per block, since each block's recurrence is independent; `wkv7_bwd` recomputes each 4-step chunk's states from the saved one and keeps the state gradient twice, once laid out by value column for the sums over keys and once by key row for the sums over values, so every sum is a clustered subgroup add and one barrier per step hands the column side's d(S^T kappa) to the row side), `heads_bwd` (direction average, bonus, value residual into layer 0's v through `dv0`, per-element contributions of xi, alpha and rho), `colsum` reductions for the per-channel parameters, then the k/v/r matmuls and the low-rank MLPs into the shift's gradient. `mda_step_begin` + `mda_step_micro` run one update of `accum` micro-batches, `mda_step_train` a one-micro-batch update, `mda_step_grad` forward + backward alone.
- `src/ckpt` -- checkpoint format (header with config + vocab hash, then the w, m, v arenas, or w alone in a weights-only file that only a load without moments accepts), atomic save, validated load (`found` tells a missing file from a loaded one).
- `src/train.c` (+ `train.h`) -- training loop: warmup-stable-decay lr, logging (the startup line gives the GPU memory allocated), periodic checkpoints, resume; `build/train [lr [checkpoint [stop [accum [adamw|muon [diffusion|block<n>[d<D>]|ar [batch [teacher [kd]]]]]]]]]` (defaults 3e-4, `models/ckpt.bin`, no stop, 2 micro-batches of 8 sequences per update, muon, diffusion, no teacher; a stop update adds the decay over the last fifth; a teacher (safetensors path) distils its next-token distributions into the clean rows of block mode or every row of ar mode, as `kd` * teacher + (1 - `kd`) * the real next token, default 1). Few large micro-batches beat many small ones: the wkv kernels run one workgroup per sequence, head and direction, and the matmuls get more rows.
- `src/import.c` (+ `import.h`) -- `build/import [weights [out]]`: a checkpoint (step 0, zero moments) from SmolLM2's weights, as RADLADS does: embeddings, norms and the FFN copied, q -> r, k -> k, v -> v (KV heads repeated over their query heads), o -> o, token shift set to the current token; the RWKV-7 parameters keep their init (gate 1, bonus 0).
- `src/check_teacher.c` (+ `check_teacher.h`) -- runs the teacher on the first `seqlen` tokens of the corpus and writes the ids and logits to `models/teacher_check.bin` for `tools/check_teacher.py`, then measures its held-out next-token bits/byte on full-size batches (the reference a distilled student's AR NLL compares with).
- `src/sample.c` (+ `sample.h`) -- held-out NELBO bits/byte (the comparable number), masked-token bits/byte, masked-fill accuracy and, in block mode, the clean rows' AR NLL, on fixed eval batches; `build/sample [checkpoint [diffusion|block<n>[d<D>]|ar]]`.
- `src/generate.c` (+ `generate.h`) -- generation over several rounds, with forwards per token, repeated trigrams, unigram entropy and, given an AR judge checkpoint, generative perplexity; `build/generate [steps [checkpoint [temp [mode [judge [policy]]]]]]`. Modes: `diffusion` (the full-length model over the whole sequence), `block<n>` (an n-token model with the clean-state cache, block by block: each block is decoded, then one more forward advances the cache over it; `block<n>d<D>` the split model, with at least 64 / n sequences so the clean rows fill the 64-row matmul tiles), `ar` (block mode with `spec0`, exact cached left-to-right sampling). Policies: `random` / `ltr` / `conf` (reveal order: random, left to right, or most confident first; fixed steps per block or per sequence), `remdm<eta>` (random order, and after every step but the last each decoded token is re-masked with probability eta, ReMDM), `spec<k>` (block mode: self-speculative decoding, the noisy rows draft up to k tokens and the clean rows' AR distribution accepts or resamples them exactly).
- `src/bench.c` (+ `bench.h`) -- the GPU memory the training config allocates, a table of both fp16 matmul kernels (64x64 and 128x128 tiles) on every shape training and Muon run, then forward / forward+backward / training-step timing on synthetic tokens plus the per-kernel GPU profile of a step, then decode-forward timing and profile of the full-length block model vs the block-length cached one; `build/bench [adamw|muon [batch [diffusion|block<n>[d<D>]|ar]]]` (defaults `muon 8 diffusion`, the training defaults; its step is one micro-batch plus the optimizer).
- `src/probe_coopmat.c` -- lists the device's cooperative-matrix configs.
- `src/probe_memory.c` -- lists memory heaps/types with GPU and host bandwidth per type.
- `src/probe_acts.c` -- for a checkpoint whose training went non-finite: finds a batch whose fp16 forward overflows, checks the fp32 forward, prints per-layer max activations.
- `src/test_matmul_f16.c` -- fp16 coopmat matmuls vs the scalar fp32 matmul, plus the scaled fp16 path on an operand far past fp16's range, both kernels with plain and transposed operands (including shapes that leave the 128x128 tiles partial in both directions), and the output stage (`alpha * AB + beta * P` from a separate buffer, fp32 and fp16 stores).
- `src/test_grad.c` -- train vs inference loss, fp16 vs fp32 backward, finite-difference check of every param's gradient along sign(g) (every matrix but the embedding randomized and every vector jittered first, so the zero-initialised low-rank A matrices are checked too), best of two step sizes and a Richardson extrapolation of the small one (tiny model, fp32 reference mode `ref32`, in diffusion, causal, block and split block mode), gradient accumulation vs summed grads, the GPU AdamW step, Muon updates vs a host Newton-Schulz, the overflow skip, one-block block mode equal to plain diffusion, block causality (no leak from later blocks, injection from earlier ones), and a block-length model with the cache equal to the full-length block model, plain and split.
- `src/test_tokenizer.c` (+ `test_tokenizer.h`) -- tokenizer file round trip, a toy BPE exercising the pre-tokenizer (contractions, space runs, isolated digits, newlines) and the merge order, and the Unicode classes.
- `src/test_ckpt.c` -- checkpoint write/read round trip through memory, with and without moments, and a weights-only file (loads, refused for resuming).
- `shader/` -- one compute kernel per file.
